# YT Ocean Travel — 專案架構

用 three.js 做的 3D 航海遊戲：在台灣、日本、韓國、北韓、中國沿海（遼寧、河北、天津、山東、江蘇、上海、浙江、福建、廣東、廣西、海南）、香港、澳門、越南、菲律賓、東南亞、南亞與中東的真實海岸線與地形之間開船、看景點、集章。中國及東南亞、南亞與中東多數國家目前只有海岸、地形與地名，尚無景點與印章。
純靜態網站，沒有後端；所有進度存在瀏覽器的 localStorage。

## 執行流程

1. `index.html` 載入 `app.js`（2D 海面 + 進度條）與 `build/ocean.bundle.js`。
2. 打包檔的進入點是 `ocean.js`。`regions.js` 讀入區域登錄表 `Data/regions.json`；各模組用 top-level await 下載簡化海岸線、總覽地形圖、各國地名、海域與景點，`data-loader.js` 更新進度條。
3. 船（或戰鬥機）附近的完整海岸線與高解析地形圖載完後，才擺放景點、城市燈光，並替所有陸地建好粗略地形。
4. 之後 `land.js` 每格依載具位置分區下載（見下方「區域登錄表與分區下載」），景點與燈光在地形圖到達或釋放後自動重貼地面。
5. `ocean.js` 的 `animate()` 每格依載具更新：船隻走手動／自動巡航、海岸碰撞與集章；戰鬥機走飛行高度、陸地降落與地形避撞，接著更新鏡頭、HUD 與繪製。

## 區域登錄表與分區下載

**資料來源與產生：** 原始資料放在 `scripts/source-data/`（各國海岸線、地形圖、`places.json`），國家清單與參數寫在 `scripts/source-data/regions.source.json`。修改後執行下列指令重新產生 `dist/Data/regions.json`、`coast/`、`dem/`、`places/`。腳本需要 Pillow 與 shapely（例如 `python3 -m venv <資料夾>`，再用該資料夾的 pip 安裝 `pillow shapely`）。
```
<venv>/bin/python scripts/build_regions.py
```
新增國家時，在 `regions.source.json` 加一筆國家（代碼、名稱、標籤、別名、海岸線檔、地形網格間距），必要時加地形圖來源，不需要改遊戲程式。國家相關的解鎖條件、成就仍寫在 `achievements.js`。

**全球資料流程（`scripts/build_world.py`）：** 新地區一律用這支腳本：在 `scripts/source-data/world_regions.json` 定義範圍、要保留的國家（ISO 代碼）、要排除的既有海岸檔與暫定解鎖條件，執行
```
<venv>/bin/python scripts/build_world.py southeast-asia <OSM land-polygons-split-4326 資料夾> <Natural Earth ne_10m_admin_0_countries 資料夾> <快取資料夾>
```
就會依 2° 格切出 OSM 陸地、用 Natural Earth 1:10m 國界分國（國界外的海岸與小島給 1° 內最近的國家）、寫出各國海岸檔、產生整區地形圖（z8、每度 200 像素）、下載 GeoNames 補地名，並把缺的國家與地形圖加進 `regions.source.json`。之後照常跑 `build_regions.py` 與 `build.mjs`。國與國之間的陸地邊界精度約 1 km（Natural Earth），海岸仍是 OSM。已完成：東南亞（新加坡、汶萊、東帝汶、馬來西亞、泰國、柬埔寨、寮國、緬甸、印尼；印尼到東經 141°）、南亞（印度、巴基斯坦、孟加拉、斯里蘭卡、馬爾地夫、尼泊爾、不丹、阿富汗）、中東（土耳其、賽普勒斯、敘利亞、黎巴嫩、以色列、巴勒斯坦、約旦、埃及、沙烏地阿拉伯、葉門、阿曼、阿聯、卡達、巴林、科威特、伊拉克、伊朗）。總覽地形圖降到每度 20 像素以控制大小。大洋洲（澳洲、紐西蘭、巴布亞紐幾內亞、索羅門群島、萬那杜、斐濟、吐瓦魯、薩摩亞、東加、吉里巴斯、諾魯、馬紹爾群島、密克羅尼西亞、帛琉，以及新喀里多尼亞、法屬玻里尼西亞、瓦利斯和富圖納、美屬薩摩亞、關島、北馬里亞納群島、庫克群島、紐埃、皮特肯群島、諾福克島等屬地；夏威夷、美國本土外小島嶼留給美洲）。中亞與高加索（哈薩克、烏茲別克、土庫曼、吉爾吉斯、塔吉克、蒙古、喬治亞、亞美尼亞、亞塞拜然；俄羅斯尚未畫，所以北邊鄰接處暫時是海；裏海已有哈薩克、土庫曼、亞塞拜然、伊朗四岸）。至此亞洲除俄羅斯外全部完成。

跨換日線或島嶼分散的地區：`area` 可給多個方框（大洋洲用東經 112.5°–180° 與西經 180°–124° 兩框），`dem.boxes` 則讓每個方框各產生一張地形圖（可附每度像素數），而且只下載陸地附近的地形圖塊，海面維持 0。`names` 可覆寫 Natural Earth 的中文國名（澳大利亞 → 澳洲）。同一代碼有多筆國界時（澳洲本土、珊瑚海群島、亞什摩群島）會合併，不會互相覆蓋。

**地名一律繁體中文（`scripts/name_places.py`）：** `build_world.py` 之後再跑
```
<venv>/bin/python scripts/name_places.py <GeoNames 國家檔資料夾> <快取資料夾>
```
它會依 GeoNames id 查 Wikidata 的中文名（zh-tw > zh-hant > zh-hk > zh，轉繁體）；沒有正式中文名的，就把地理通名翻譯成中文（Pulau→島、Teluk→灣、Huyện→縣、Island→島…），其餘部分自動音譯。韓文依漢字音轉漢字，日文假名逐音轉字，拼音轉回漢字，日文新字體轉舊字（広→廣）。音譯名只是近似。原名放進第一個別名，所以用原文搜尋仍找得到。已經是中文的地名不會被改動。海岸提示也改用中文國名（「日本海岸 · 3.2 km」）。

**新增國家的原始資料（以中國沿海為例，較早的手動流程）：** 三支腳本把下載的資料轉成 `scripts/source-data/` 的格式，下載檔放在專案外：
- `scripts/build_coast.py <preset>`：預設組 `vietnam`、`china`、`philippines`、`borneo`（`vietnam` 要先跑，`china` 會把越南的陸地從廣西切掉）。從 OpenStreetMap 陸地多邊形（`land-polygons-split-4326.zip`，約 930 MB）切出遼寧到廣西的沿海省市與海南（geoBoundaries 省界外擴 0.3° 決定範圍；北京一併納入以免河北中間留洞）及香港、澳門（OSM 行政界線，`scripts/source-data/boundaries/`）的海岸線；菲律賓整國取 OSM 國界（含領海，簡化 0.005°）內的陸地，東經 116.8° 以西（爭議中的南沙）不收；越南整國取 OSM 國界（簡化 0.001° ≈ 100 m）內的陸地，東經 109.6° 以東（西沙、南沙）不收；婆羅洲依汶萊、馬來西亞國界分出兩國，其餘歸印尼，搜尋範圍邊界切到的島與蘇拉威西西岸不收；已屬其他國家的陸地會切掉（鴨綠江北韓側），大半屬於台灣的島（金門、馬祖）不收。
- `scripts/build_dem.py`：下載 AWS Terrain Tiles（Terrarium）重投影成經緯度格網高度圖（z8、每度 200 像素；中國東經 104.3–126°、北緯 18–43.6°，越南東經 102.1–109.6°、北緯 8.3–23.5°，婆羅洲東經 108.3–119.6°、南緯 4.4°–北緯 7.6°）。
- `scripts/build_places.py`：從 GeoNames 國家檔挑出陸上與近海地名，中文名轉為繁體。已存在的地名（同類型、位置相差 0.01° 內）沿用原名稱與別名，GeoNames 不再產生的舊地名（例如手動加入的火山）也保留。
三支都需要 shapely、pyshp、numpy、Pillow、opencc-python-reimplemented。產生後再跑 `build_regions.py`。中國範圍只到上述省市的邊界，內陸邊界以外沒有陸地（戰鬥機飛到內陸會看到地面結束）。寮國、柬埔寨不在範圍內，越南西側國界以外沒有陸地；馬來西亞與印尼已擴充至半島及群島地形範圍。
- `scripts/update_seas.py`：從 Natural Earth 海域多邊形新增或替換 `dist/Data/seas.json` 的海域（南海西段、北部灣、瓊州海峽、泰國灣、爪哇海、望加錫海峽，以及菲律賓周邊的蘇祿海、西里伯斯海、米沙鄢海、保和海、錫布延海、薩馬海、萊特灣、達沃灣等），範圍到南緯 5°。台灣的地形誇張倍率（1.9）只套用東經 119.95° 以東，避免福建沿岸被拉高；澎湖、金門、馬祖改用一般倍率。

**執行時（`land.js`）：**
- 海岸分兩層：一開始只有粗略海岸層（大島、約 1.6 km 精度）；船或戰鬥機 170 單位內的區塊換成完整海岸（含小島），離開 230 單位後換回粗略層。兩層的島數不必相同，換層時直接替換 `landIslands` 裡該區塊的島（原地修改，其他模組持有同一陣列）。碰撞、離岸距離、導航、地圖都讀這份陣列，換層時 `landVersion` 加一，導航規劃器會用新海岸線重建；景點的外海集章點也在完整海岸到達後重算。
- 每國海岸依 2° 格切開（`cut` 標記被切開的邊不是海岸），大陸也能分塊下載。
- 地形高度：附近已下載的地形圖塊優先，其餘用總覽地形圖。圖塊到達或釋放時發出 `onLandChange`，`ocean.js` 隔一秒批次把景點、燈塔與城市燈光重貼地面。
- 地形網格：每國依登錄表的間距切成方塊，只為鏡頭 1,500 單位內的陸地建立，超過 1,800 單位就整塊釋放。粗略網格用粗略海岸層＋總覽地形；靠近、且所需完整海岸與地形圖塊都到齊時，才建精細網格；兩者都在每格約 6 ms 的預算內由近而遠建立。
- 同時最多 4 個下載。下載失敗會留在簡化版本，下次移動時重試。
- 海面與天空是有限大小的網格（10,000 單位），每格跟著鏡頭移動；水波紋以世界座標取樣，不會跟著滑動。地圖擴大到遠離原點時不會出現黑邊。
- 鏡頭近平面隨鏡頭高度調整（高度 × 0.02，介於 0.05–40）：從海圖或高空看時深度精度足夠，接近海平面的平原不會和海面互相閃爍。

**自動導航已移除（2026-10-25）：** 尋路（A*、遠洋格網 `nav/sea-grid.png`、背景 Worker）、搜尋框、地圖點擊導航、一鍵環台與「自動導航抵達」成就都已刪除。船隻改為手動航行（W 按住）或自動巡航（E），長距離移動用各國的傳送點（P）。

**世界東西相接（`geo.js`）：** 經度從接縫子午線 `SEAM_LONGITUDE`（西經 168°，位於白令海、2° 格線上，與 `regions.source.json` 的 `world.seamLongitude` 相同）往東排 360°，x 介於 `WORLD_MIN_X`–`WORLD_MAX_X`（一個世界寬約 9,174 單位）。船或戰鬥機越過一端就從另一端出現（`ocean.js` 的 `wrapVehicle`，鏡頭與自動導航航點一起平移）。接縫 12° 內的海岸區塊與地形圖塊另有一份平移一個世界寬的副本，越過前就看得到對面。長程航線在接縫兩側保持連續座標，局部規劃時再移回同一個框內計算。南北限制在北緯 75°、南緯 60°（`world.north`、`world.south`）。世界地圖（Tab）只涵蓋登錄表裡有陸地的範圍，探索紀錄另存起點（`relax-explored-origin-v1`），範圍改變不會錯位。

**遠方座標精度（量測結果）：** 把整張地圖暫時移到離原點約 9,000 單位處比對：地形、海岸、景點外觀相同；只有海面與天空因為固定大小而消失，已改成跟著鏡頭。依 32 位元浮點計算，9,000 單位處頂點誤差約 0.001 單位，在一般鏡頭距離約 0.5–1.3 像素，暫不需要「原點跟著船移動」。

## 遊戲進度與解鎖

- **開發階段：** 所有國家的海域、景點及集章直接開放；原有環台、環日本及國家達人等成就仍可累積。
- **恢復正式解鎖鏈時：** 將 `achievements.js` 的 `DEVELOPMENT_ALL_COUNTRIES_OPEN` 改為 `false`；原規則依序是環台開日本、環日本開韓國／北韓／中國／香港／澳門／越南，再由韓國及北韓達人開放其他國家。

解鎖條件寫在 `scripts/source-data/regions.source.json`：每國的 `unlock` 列出需要的成就 id（環島 `circuits` 的 id，或 `master:<國名>` 代表集滿該國印章），`arrival` 是抵達海岸的成就。`circuits` 定義環島中心點、北緯下限（日本不算琉球）與存檔欄位（沿用舊存檔的 `sectors`、`japanSectors`）。`achievements.js` 保留正式解鎖規則與存檔，但開發開關生效時不阻擋國家海域及集章。

存檔都在 localStorage，多個分頁同時開也會自動合併，不會互相覆蓋：

| 存檔 | 內容 |
|---|---|
| `relax-achievements-v1` | 成就與解鎖 |
| `relax-journey-v1` | 航海日誌、印章、達人 |
| `relax-explored-v1` | 世界地圖探索度 |
| `relax-quality` | 畫質 |
| `relax-audio` | 音量與開關 |
| `relax-ship`、`relax-paint` | 選的載具與配色 |
| `relax-boat-v1` | 帆船／遊艇原有航程位置與航向，格式維持不變 |
| `relax-aircraft-v1` | 戰鬥機位置、高度、航向、速度與飛行狀態 |

戰鬥機短按 F 垂直起飛、長按 F 爬升；短按 L 在平緩且無景點障礙的陸地降落、長按 L 下降；H 切換滯空。W/S 前進減速（滯空可倒退），A/D 或左右方向鍵轉向，E 隨時開／關 Turbo，沒有冷卻或自動結束；減速、滯空或降落也會關閉 Turbo。升降只用長按 F／L（Space、Shift 已移除）。飛行高度上限為儀表顯示的 10,000 m；山脈與景點過近時會自動拉升。飛行期間停用海上自動導航、集章與航行成就；切回船隻時恢復先前海上位置。
追尾鏡頭維持固定視角及距離；雙引擎各有一束向後延伸的黃白亮芯、橘紅外焰與少量同向火花，長度隨速度增加，速度 HUD 及引擎聲亦由飛行速度驅動。夜間機身會呈現柔和自發光，滯空或換回船隻時尾焰收斂；引擎聲可在設定面板個別靜音和調整音量。
日出、日落、夜晚各維持 2 分鐘並自動循環；T 鍵或設定面板可立即切換，切換後從該時段重新計時。

## 地景精緻化

- 真實海岸線、航行碰撞及 DEM 仍是地理基礎；岩石微紋理、近岸水色與鵝鑾鼻岩群為視覺裝飾，不表示新增實測資料。
- 地形材質使用世界座標，避免分塊紋理接縫；小島三角形增加內部高度取樣。
- 景點近景保留既有模型與夜間發光材質；中、遠景使用材質分組的垂直輪廓，只有三角形數少於原模型 80% 時才採用。簡單模型不另外增加代理模型。
- 接觸陰影隨地形取樣，海外高度圖載入後重貼地面；海上橋梁與自然景點不套建築基座。陰影為程序近似，未宣稱離線烘焙 AO。
- 太陽陰影只在附近景點啟用，更新上限約每秒 8 次；中畫質 1024、高畫質 2048，低畫質關閉。地表接收陰影，不替整個國家重繪陰影。
- GLB 僅載入一份並以 InstancedMesh 重複使用；載入失敗保留程序地景。樹群與岩群數量隨畫質下降。
- 鵝鑾鼻為完整示範區；其他景點共用材質、LOD 與接地系統，未逐一更換為外部建築模型。

### 操作

方向鍵 ↑／↓／←／→ 與 W／S／A／D 可混用，單獨放開一組鍵不會清除另一組仍按住的輸入；搜尋框、文字區、選單及可編輯文字保留原生鍵盤功能。操作說明與載入中的海面亦支援方向鍵。

海豚改用沿速度切線俯仰的拋物線：出水抬頭、入水低頭、空中維持起跳方向與水平速度，入水後限速回到隊形。船長在船體局部座標量測並快取，轉向／搖晃不會改變海豚尺寸與跳高。水花按照頭部實際穿越海面觸發，減少跳躍高度、側滾及粒子量。

驗證：`tests/movement.test.mjs` 涵蓋方向鍵混用、輸入焦點、手動／自動巡航、海豚俯仰與游動限速；`tests/shore-limit.test.mjs` 涵蓋從港灣開出窄口。

景點可視性驗證：`tests/landmark-readability.test.mjs` 檢查最小高度、塔樓高低順序、展示配置分離、非對稱底座與陸地約束。日本與高雄模型測試以放大後的實際幾何邊界檢驗新配置，不再以縮小模型避免重疊。

### 景點可達性

內陸景點的外海集章點會檢查輪廓外側是否存在至少 2.2 公里離岸空間，跳過被其他陸地覆蓋的邊界及不可通行裂縫。景點展示底座與橋墩是手動航行的障礙，橋梁通道不整片封鎖。

集章使用外海點 2 公里範圍與展示模型邊緣 6 公里範圍，已存印章維持不變。多枚印章依序顯示；航行與海圖提供固定螢幕尺寸的景點名稱、距離、完成狀態及集章點旗標。「集章指示」列出附近未取得景點的方位與距離。

### 時間與目錄整理

從專案根目錄執行建置及測試指令。時間僅提供日出、日落、夜晚，T 依序切換；沒有正午或自動循環。日出太陽在東方，採較清透的藍粉晨光與冷色海面；日落太陽在西方，採橘紅霞光、較濃大氣與暖色反射。夜晚保留月光、星空與船燈。`day-cycle.js` 集中管理時間與光色，`sky-extras.js` 配合晨昏調整雲霞。

根目錄的一般檔案只有 `開始遊戲.command`、`開始遊戲.bat`。雙方均啟動 `scripts/serve.py`；伺服器依自身路徑定位 `dist/`，不受工作目錄影響。`.git/`、`.claude/`、`.openai/` 保留工具原有位置；`node_modules/` 保留套件標準位置。網站仍由 `dist/` 發佈，現有網址不變。

海上船型在 `dist/traffic-ships.js`，供 `sea-life.js` 共用，包含漁船／集魚燈船、貨輪與遠近 LOD。

### 統一景點預覽

`http://localhost:8743/landmark-review.html` 是全部景點的共用入口，從遊戲「操作」面板也能開啟。以遊戲 `Data/landmarks.json` 生成 116 筆目錄，台灣 25、日本 29、韓國 17、北韓 2、菲律賓 10、香港 5、澳門 5、越南 5、汶萊 3、馬來西亞 6、印尼 4、新加坡 5；預覽整合各地實景特徵、模型參數與參考連結。預覽提供國家篩選、名稱／別名搜尋、上一個／下一個、旋轉縮放及日夜切換。原有 `?model=nsysu` 等網址繼續有效；共用 `peak` 類型以國家前綴分辨，兩座橋梁保留專屬 ID。山岳預覽只顯示山頂模型／標記，頁面會註明完整山體在遊戲地形中。

`landmark-review-catalogue.js` 負責整合與篩選；預覽仍共用 `LANDMARK_BUILDERS`，沒有複製另一套模型。新增景點資料後會自動出現在同一預覽入口。

汶萊三處與馬來西亞六處由 `brunei-malaysia-models.js` 建模、`brunei-malaysia-reference-data.js` 保存官方旅遊與遺產來源。模型採可辨識的微縮實景特徵：皇宮與清真寺穹頂、烏魯淡布隆樹冠步道、雙子星塔空中橋、蘭卡威懸索橋、神山裸露花崗岩峰、丹絨亞路亞魯木樹、馬六甲紅屋及布城湖畔粉紅清真寺。九處皆與遊戲共用模型，並按原地理座標產生近海導航及集章停靠點。

印尼四處與新加坡五處由 `indonesia-singapore-models.js` 建模、`indonesia-singapore-reference-data.js` 保存官方旅遊、景點營運方與 UNESCO 來源。峇里島德格拉朗的 Subak 梯田、布羅莫的沙海與火山口、日惹王宮的爪哇亭頂、婆羅浮屠的方形與圓形佛塔台層，以及新加坡的擎天樹、魚尾獅、環球影城入口地球、星耀樟宜瀑布、克拉碼頭河岸店屋都各有專用模型，供遊戲與預覽共用。

### 勝利星村與平溪天燈

台灣目前 19 處、全部 77 處。`taiwan-village-models.js` 在共用 `LANDMARK_BUILDERS` 註冊 `shengliVillage` 與 `pingxiLanterns`，遊戲及統一預覽使用同一模型。勝利星村位置採觀光署公布座標（22.678632, 120.48449），黑瓦官舍、綠窗、紅門及樹蔭庭院參考將軍之屋。平溪天燈以新北市觀光局的十分老街與天燈實景為場景（25.04269, 121.77667），包含鐵軌、混合屋頂店屋、雨棚、列車及開口紙天燈。兩者為程序微縮重建，街廓、比例和天燈位置經濃縮，非實測；`realHeight` 為展示用參數。

新增兩枚獨立印章，存檔鍵及既有印章名稱不變。搜尋、集章冊、預覽及計數從景點資料自動生成；內陸位置沿用外海停靠點及模型邊緣集章區。參考連結保存在 `taiwan-reference-data.js`，照片不作為遊戲貼圖。

### 勝利星村遊戲位置與展示範圍

依玩家需求，勝利星村以獨立 `displayLocation`（22.52,120.52）放在佛光山更南方，遊戲內中心間距約 28 公里；原始實景座標僅留作參考。模型、地圖名稱、外海導航停靠點及集章邊界共用展示位置，兩者標籤只顯示景點名稱。`preserveLocation` 鎖定展示錨點，附近可移動景點避讓；`maxDisplayFootprintKm:4` 保留聚落的展示範圍上限。原有印章名稱與存檔鍵不變。

### 海岸與離島實景景點

目前台灣 25 處、全部 93 處。`taiwan-coastal-models.js` 提供三仙台、花瓶岩、龜山島、澎湖跨海大橋、雙心石滬，共用於遊戲與預覽；參考來源放在 `taiwan-reference-data.js`。三仙台採八拱橋永久外觀（不含臨時整修設施）、花瓶岩採海蝕珊瑚岩細頸寬帽、澎湖橋梁採公路橋面與半圓橋門、雙心石滬採退潮意象的疊石與導魚堤。均為原創程序近似，並非測繪模型。

小港機場 `airport-model.js` 參考高雄國際航空站與民航局機場圖，以東西向 09/27 跑道、北側平行滑行道、國際與國內航廈、空橋、停機坪和塔台構圖。兩架飛機停靠，另外兩架依序起飛、清空跑道、降落；起飛與降落各約 4.5 秒，遊戲和共用預覽使用同一動畫。模型展示倍率為 0.60；陸上機場仍以安全外海停靠點集章。此模型為便於海上辨識的程序化微縮意象，非實際航空圖資。

龜山島在 `taiwan-coastal-data.js` 保留與遊戲相同的海岸輪廓；`land.js` 僅跳過這座島原本的地形渲染，航行碰撞／導航仍保留完整原始海岸，避免島形疊加。世界尺寸場景以 `worldSized` 跳過一般建築的高度標準化，避免低矮石滬放大成數十公里寬。五處均有獨立印章、搜尋別名、外海停靠點及預覽頁入口。
